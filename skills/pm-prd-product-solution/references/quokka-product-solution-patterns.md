# Quokka 产品方案历史 PRD 模式提炼

来源样例：

- 【Quokka】v1.1.0支持图片模板&图片资产
- 【Quokka】v1.1.0支持双图模板
- 【Quokka】v1.1.0 +号模板流程
- 【Quokka】v1.1.0 +号入口&相册页
- 【Quokka】V1.1.5+号Enhance流程
- 【Quokka】v1.2.0+号视频生成流程
- 【Quokka】1.4.0 Generate迭代&支持remake
- 【Quokka】v1.4.0 外部视频模型&V6接入

## 1. 核心共性

Quokka 的产品方案不是泛泛写功能描述，而是把「页面 / 模块 / 需求点」拆成可评审表格。

常见表头：

```markdown
| 需求点 | 详情 | 示意 |
```

或：

```markdown
| 功能/页面 | 需求详情 | 参考图 |
```

本质一致：左列是评审对象，中列是可执行规则，右列承接 UI 图 / Figma / 画板 / TBD。

需求详情单元格通常按以下顺序展开：

1. 展示内容 / 静态样式
2. 触发方式 / 用户操作
3. 跳转或下游流程
4. 输入限制 / 参数规则
5. 权益 / 积分 / 计费
6. 异常 / 兜底 / 低版本兼容

## 2. 按需求类型拆行

### 模板类

参考：图片模板、双图模板、+号模板流程。

典型行：

- 模板首页
- 模板详情页
- +号模板选择页 / +号生成入口
- 上传图片 / 相册页
- 模板创作页 / 进行创作
- 生成等待页 & 视频详情页
- 资产页
- 运营后台

必须写清：

- 新增模板类型是否需要用户感知，例如图片 icon、Image 标签、双图无需感知。
- 模板封面 / 模板名称 / Channel 排序是否 follow 运营后台。
- 上传张数：单图 / 双图 / 多图，文案如 `Upload x Images`。
- 相册页是否复用公共相册逻辑，是否过滤图片 / 视频 / GIF。
- 创作页输入区：预览、替换、删除、裁剪、大图、拖拽排序。
- Create 按钮高亮条件和积分展示。
- 运营后台字段放单独行，别混进端上行。

### +号入口与相册类

参考：+号入口&相册页。

典型行：

- +号功能入口面板
- +号相册页
- 最近使用
- 本地相册 & 资产
- 选择引导框
- 项目选择器
- 大图模式
- 边界场景

必须写清：

- 点击 + 号后的面板打开 / 收起方式。
- 每个入口文案和跳转目标，例如 `Use Effect`、`Generate Video`、`Enhance Quality`。
- 相机授权、相册授权、未授权停留逻辑。
- 最近使用：本地存储、max 数、时间倒序、空态不展示。
- 本地相册 / Asset：来源定义、分类切换、过滤规则、展示顺序。
- 项目数量要求：明确数量 vs 无明确数量时，选择器展示不同。
- 多来源选择无需去重，但共享输入数量上限。

### Generate / 视频生成类

参考：v1.2.0+号视频生成流程、v1.4.0 外部视频模型&V6接入。

典型行：

- 前置逻辑
- 起始页
- 上传图片
- 进行创作
- 参数面板 / 模型选择
- 创作面板
- 会员权益
- 其他兼容

必须写清：

- 入口层是否统一为 Generate，底层能力如 it2v / transition / fusion / reference / keyframe。
- 起始页：输入框、showcase、按钮置灰、参数入口置灰。
- 上传页：min/max、0 张 / 未满 / 达上限三种状态。
- 单图 / 双图 / 三图模式分别写，不要混成一句。
- Reference vs Keyframe 的差异：图片标签、帧位、prompt 文案、参数项。
- Prompt 输入：是否必填、字数限制、`@` 调用、保存/收起规则。
- 参数面板：resolution / duration / audio 的默认值和展示条件。
- Create：可点击条件、积分实时更新、模型/模式调用链路。
- 外部模型：选择器、参数联动、会员拦截、失败态。

### Enhance / 大文件上传类

参考：V1.1.5+号Enhance流程。

典型行：

- 功能使用权限
- 主页面交互 / 上游路径
- Enhance 起始页
- 相册页
- 创作页 - 用户输入图片
- 创作页 - 用户输入视频
- 裁剪页
- 付费引导弹窗补充权益文案
- 图片/视频限制提示
- 上传等待态 / 上传队列 / 资产页入口

必须写清：

- 图片和视频分开写，二者上传时机不同。
- 图片可提前预传；视频通常点击 Enhance 后再上传。
- 视频长时长权限：会员 / 非会员上限不同。
- 非会员超时长进入裁剪页，裁剪页必须完成裁剪才能继续。
- 生成前判断顺序：免费次数 → 积分 → 付费引导。
- 上传中状态：Pending / Uploading / Failed / Check Later / Cancel Upload。
- 上传队列入口、文件命名和源文件消失状态是产品方案的一部分。
- 边界文案要写原文，例如 `Only videos under 10 mins supported.`。

### Remake / 视频详情迭代类

参考：1.4.0 Generate迭代&支持remake。

典型行：

- keyframe 迭代
- 视频详情页相关迭代
- 支持重新生成
- 低版本 / 会员 / 模板 / 模型边界

必须写清：

- 前置场景和生效场景分开写。
- 对多图 keyframe，写清图片间 icon、选中态、prompt 分段、保存与删除联动。
- 视频详情页展示生成详情：图片、prompt、Frame 标签、展开/滚动。
- remake 入口位置和点击后的工程信息继承。
- 边界 case 必须列明：低版本隐藏、会员过期、模板下线、模型下线及 toast。

## 3. 小点化组织方式

Quokka 产品方案的观感不是大段说明，而是「分组标题 + 小点规则」。旧 PRD 和用户手改稿共同体现出这套结构：

```html
<p><b>交互逻辑</b></p>
<ul>
<li>回退逻辑：
  <ul>
  <li>触发条件：当前已选模型因图片数量 / Use for 变化变为不可用。</li>
  <li>回退目标：优先回退到 PixVerse V6.5；若不可用，再回退到 PixVerse V5。</li>
  <li>同步刷新：厂商 Tab、Model series、gems 消耗与参数面板。</li>
  </ul>
</li>
<li>置灰逻辑：
  <ul>
  <li>判定沿用 v1.4.0 的模型可用性规则。</li>
  <li>本期变化是不再隐藏不可用项，改为外显置灰。</li>
  </ul>
</li>
</ul>
```

落笔规则：

- 粗体标题负责切模块：`选择模型`、`参数面板`、`交互逻辑`、`兼容逻辑`、`会员权益`。
- 一级 bullet 负责切小主题：`默认值：`、`展示规则：`、`判定规则：`、`状态：`、`排列规则：`、`示例：`。
- 二级 bullet 才写具体规则，一条只写一个判断或动作。
- 长句必须拆：出现多个条件、多个动作、多个同步项时，拆成二级 bullet。
- 开发要能按 bullet 拆任务，测试要能按 bullet 写用例；如果一条 bullet 不能独立验收，说明还没拆够。

## 4. 写作注意

- 表格左列不要只写「流程」，要写可定位的页面或模块。
- 表格中列「需求详情」使用分组标题 + 缩进无序列表：`<p><b>分组标题</b></p><ul><li>规则</li></ul>`。不要用 `<br>-` 把多条规则堆成一个长段落。
- 一级 bullet 不写长段落；一级放小主题，二级放规则。需要解释时，用 `示例：` 单独成点。
- 若某行复用旧文档，必须写「复用 xxx 的 xxx 逻辑」，不要只写「复用线上」。
- 删除线内容来自旧文档读取时可作为历史参考，成稿时不要保留删除线，除非用户明确要保留评审痕迹。
- UI 图缺失不阻塞产品方案，参考图列写具体 TBD。
- 图已经在飞书中存在时，更新飞书要保留图片 block，不要 overwrite 全文。
