# FayeMax / Quokka PM 文档写作规范（Part 1 原文提炼）

来源：[【FayeMax】文档写作 SOP & 业务 Background](<FEISHU_DOC_URL>) Part 1。所有 `pm-*-doc` 类 skill 的输出须与本规范一致。

## 1.1 语言风格

- 务实、直接，不废话，无多余客套。
- 用词专业但不绕弯：不说「我们认为可以考虑」，直接说「建议」或「方案」。
- 情绪中性、陈述事实；做判断时有明确立场（「符合预期」「超出预期」「需要优化」）。
- 并列用 `&`，逻辑关系用 `/`、`→`。
- 标点偏少，可用空格或换行控制节奏，整体阅读要快。

## 1.2 表达习惯

- **结论前置**：重要结论在文档顶部或章节开头，数据与例证在后。
- 善用「前置思考」「写在前面」等模块，先搭框架再展开。
- **关键假设显式写出**，并说明「为什么这样想」（业务假设 + 核心逻辑）。
- 善用对比框架（如 Quokka vs 竞品、新用户 vs 老用户、预期内 vs 预期外）。
- 数据引用精确，标注**来源期间与口径**（例：`DAU 1.5-2k`、`渗透 0.14%`）。

## 1.3 排版与格式

| 元素 | 规范 |
|------|------|
| 标题层级 | H1 文档标题，H2 大章节，H3 子章节；最多 3 层 |
| 表格 | 多用表格承载并列信息（竞品、优先级、埋点、范围等） |
| 列表 | 并列用 bullet；有顺序用 ordered；超过 5 条建议改表格 |
| 引用 / callout | 前置声明、补充说明、重要假设用引用块或 callout |
| 图片 | 竞品截图、数据图、原型图放在对应段落下方 |
| 链接 | 上下游文档内链；外部（Figma、看板）单独列出 |
| 优先级 | `P00 > P0 > P1 > P2`，不用「高/中/低」 |
| 负责人 | `@姓名`，多在 TODO 表 |
| 版本 | `v1.0.0` / `v1.1.0`，与迭代节奏绑定 |

## 1.4 常用句式（可直接化用）

**开篇（结论前置）**

- 「核心结论：XXX，并跑通 XXX 策略」
- 「基于 [上游文档]，Focus 到 [具体场景]：」
- 「问题：XXX / 假设：XXX / 路径：XXX」

**分析框架**

- 「为什么不：XXX / 为什么行：XXX」
- 「定量 → 定性 → 洞察」
- 「预期内假设是否有结论 / 预期外是否有新 Insight」
- 「下探 XXX 来看：…」「拆分漏斗：…」

**结构组织**

- 「先看功能 → 再看参数 → 最后看竞品」
- 「Step1… / Step2… / Step3…」
- 「整体来看：XXX」（段尾收束）

## 跨文档统一要求

撰写或修改**任意**业务规划、PRD、数据复盘类文档时：

1. 先满足本节 1.1–1.4。
2. 再满足对应文档类型的结构模板（见各 `pm-*-doc` skill）。
3. 禁止为凑篇幅加空话、模糊优先级、或只摆数字不给「是否符合预期」的判断。
